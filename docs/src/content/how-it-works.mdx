## How it works

Memory systems such as *Mem0* retrieve relevant facts and pastes them into the prompt, so the serving engine prefills the same **text** again on every request.
**Time-to-first-token (TTFT)** then grows with the retrieval budget *k*, even though the memory is reused across requests.

InferScale replaces that repeated prefill with reusable KV state.
It precomputes each fact's KV once, keeps it on the GPU next to the fact's embedding, and at serving time injects the KV of the retrieved facts directly into vLLM's paged cache.
It plugs into vLLM through the KV-connector interface, so it needs neither engine modifications nor model fine-tuning.

For a given query:

1. The query is embedded with the retrieval embedding model.
2. GPU accelerated vector search via Jasper returns the top-*k* facts.
3. Each hit's fact id is mapped to its entry in the KV store.
4. The facts' pre-RoPE keys and raw values are fetched from GPU memory, or streamed from host memory when the KV store is offloaded.
5. Chunked RoPE lays the facts out after a chat-template header and rotates their keys.
6. The KV connector scatter-copies the rotated KV into the request's paged cache blocks, so vLLM skips their prefill.
7. vLLM prefills only the query, whose tokens attend to all of the injected KV, and decodes the answer.

### Chunked RoPE

Rotary position embedding (RoPE) is a method used in modern Large Language Models (LLMs) to tell the transformer
 the order of words in a sequence. However, RoPE rotates each key by its position, so a key cached at one position is wrong at any other.
InferScale stores every fact's keys **before** rotation.
When a request arrives, it concatenates the retrieved facts and applies RoPE once at their final positions, so the same precomputed KV is valid wherever retrieval places it.

### Context-window encoding

Encoding facts individually loses the cross-fact context that a joint prefill would provide.
InferScale encodes each fact together with up to *w* preceding chunks, such as earlier conversation turns, and caches only the target fact's KV.
The window is used only while precomputing, so it does not add to inference latency.
